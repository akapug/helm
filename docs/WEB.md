# helm web — the browser surface

`helm web` serves the whole station as one self-contained page — no CDN, no
external assets, Python stdlib only. Its source is split by owner-visible
section under `helm/web_ui/`; `manifest.txt` fixes the global CSS → markup → JS
order, and `helm.web_ui_loader` joins the raw bytes on every request without
inventing a separator. The browser still receives one document, one `<style>`
scope, and one classic `<script>` scope. It is a projection of what the CLI
already answers: every view has a terminal equivalent, and the small set of
browser mutations maps one-to-one onto CLI verbs.

```console
$ helm web            # http://127.0.0.1:7433
$ helm web --port 8080 --open
```

## The four pages

Four top-level pages: **Work · Chat · Fleet · History**. Only Fleet has a section row (credit, seats, sessions, configs, boxes); Work, Chat and History are one page each. Every retired view id still lands on the page that took it over — `#board`, `#helm`, `#scheduler` → Work; `#ledger` → History; `#storage` → boxes.

## Security posture

- **Loopback only.** The server binds `127.0.0.1` (default port **7433**);
  there is no listen-on-all option. Put a reverse proxy with its own auth in
  front if you ever need remote access — helm itself will not do it.
- **Host/Origin validation.** Every request's `Host` (and `Origin`/`Referer`
  when present) must be a loopback literal for the bound port
  (`127.0.0.1:<port>`, `localhost:<port>`, `[::1]:<port>`) — anything else is
  403. This is the DNS-rebinding defense: a hostile page re-resolved to
  loopback never reads a response.
- **The mutation token.** Every POST demands
  `Authorization: Bearer <MUTATION_TOKEN>` — 403 without. The token is minted
  fresh per process and handed to the UI by template substitution
  (`__HELM_TOKEN__` in the assembled UI source is replaced at serve time; the
  fragments on disk stay raw). `HELM_API_TOKEN` (or a declared predecessor's
  `<NAME>_API_TOKEN`; see [local names](ENVIRONMENT.md#local-names)) pins it —
  set that when a script or a long-lived service needs stable POST access.
  A tab that outlives the process (the unit recycles hourly by design) holds
  a dead token; the UI self-heals on the resulting 403 by re-reading its own
  served page for the live token and retrying the mutation exactly once — a
  genuine forbidden still surfaces loudly.
- **Bounded writes.** POST bodies over 64 KB are rejected; every mutation is
  reversible by construction (renames, moves-to-trash, backups — the
  archive-not-delete law).
- **Graceful degrade.** A subsystem that is absent or misbehaving answers
  `{"unavailable": true}`, never a 500 that takes the page down.

There is also NO WINDOW: the card shows the newest lands whenever they happened and every row carries its own age, so "the newest land was three days ago" is a true answer he can act on rather than an empty list he has to interpret. `total` is a REAL count — the ledger holds every landed close — so `rows_truncated` is a display budget disclosing itself over a MEASURED population (`newest 6 of 434 recorded lands`) rather than the lower bound the old grammar was limited to; a truncated body that cannot name a total says so instead of printing a number. `task` is the task number the integrator wrote into the close evidence this same event carries, READ and never JOINED: a lookup against `helm task`'s own ledger would be the second source the ruling forbids, and a close naming none renders NO TASK rather than a blank. `gate` is the row's verification token and an absent one renders UNVERIFIED, never verified. `on_trunk` keeps its name and its landed_ever (HISTORICAL) semantics but is now READ off the recorded `close_proof_mode` — the closing ladder already proved the land at close time against the trunk it names in the same event, so re-asking git would buy no new fact and would rebuild the second reading this card exists to delete. It is TWO-STATE, not three: `true` with `how` naming the recorded mode, and `null` when the record carries none. There is deliberately no `false`, because a `landed` close IS the record asserting the land and a card may not contradict the row it renders; when NO row carries a proof the card says so once in words, computed over the whole answer rather than over the folded group primaries. `fold_only`, `window_total` and `window_s` are GONE from the envelope with the reader that needed them, and a `witnessed` receipt badge went with them — the close event is the record now, and a second index read beside it is exactly what one source means. `age_s` is stamped at RESPONSE time like `read_age_s`. **Two ages, because the cards ask one question and the build clock answers another**: `read_age_s` is the READING's age — the build, or the newest fingerprint match that confirmed every input unmoved since it (`web_cache.verified_at`, stamped only for a body built under the matching mark, never for one a rebuild in flight is about to replace) — and `projected_age_s` is the projection's own. The cards judge their freshness bound on the first and print the second beside it when they differ; judging on the build clock alone let the cap plus a rebuild age a body to 370s against a 180s bound, so every land-pipeline band rendered STALE for most of each cycle over a ledger nobody had written to. `/api/owed` carries the same pair. And `native_chain` = `{count, verified, detail, head_index, unavailable}` — the local attest-chain summary (`premise.verify_chain()`, re-hashed per build). It STILL carries its OWN `unavailable` and is still independent — it reads the premise store, so it answers beside an UNKNOWN lands reading — while `recent_lands` now shares the dispatch ledger's fate by design (see above): one flag would render a readable half as UNKNOWN, and a card with a source of its own is a card free to disagree with the command line |

## POST endpoints

All demand the bearer token; bad requests return `400` with a class-only
`error`/`code`, while a stale config save returns `409 conflict`. `web.POST_API`
is the authority on the set; the surfaces below are its owner-facing doors, and
nothing else in the browser may write:

**On the page, every one of them rides `post()`** — the helper that attaches the
per-process bearer, re-reads a stale one and retries once, and raises the
server's own `error` sentence. Its sibling `j()` is the READ helper and takes
`(url, ms)` only; it refuses a request body rather than downgrading it to a GET,
because that downgrade shipped once and cost the work tab its comment button:
the route, the handler and the token were all healthy while the page quietly
asked for a GET at a POST-only path and the owner read `404` in a toast.

| endpoint | payload | effect |
|---|---|---|
| `/api/skills/toggle` | `{"path": <skill dir>}` | disable/enable — a reversible rename to/from `<skill>.disabled` |
| `/api/skills/delete` | `{"path": <skill dir>}` | move to `~/.cache/helm/skills-trash/` — never destroyed |

A scripted example:

```console
$ export HELM_API_TOKEN=$(openssl rand -hex 16)
$ helm web &                       # server now honors this pinned token
$ curl -s -X POST http://127.0.0.1:7433/api/prune \
    -H "Authorization: Bearer $HELM_API_TOKEN" \
    -H "Content-Type: application/json" \
    -d '{"sid": "3f2a", "dry": true}'
```

## Running it as a service

The deployment that runs live is a systemd **user** unit. Install helm on
your PATH first (`ln -s <repo>/bin/helm ~/.local/bin/helm`), then:

```ini
# ~/.config/systemd/user/helm-web.service
[Unit]
Description=helm web — the personal knowledge home UI
After=default.target

[Service]
ExecStart=%h/.local/bin/helm web --port 7433
Restart=on-failure
RestartSec=5
# optional: pin the mutation token for scripted access
# Environment=HELM_API_TOKEN=<your-token>

[Install]
WantedBy=default.target
```

```console
$ systemctl --user daemon-reload
$ systemctl --user enable --now helm-web
$ systemctl --user status helm-web
```

`loginctl enable-linger $USER` keeps it running when you are not logged in.

The server on the console port also runs the **stop-facts leg**: the one
writer of `_global/web-cache/stop-facts.json`, the facts every seat's Stop
hook reads instead of folding the dispatch ledger and asking git per lease
(docs/HOOKS.md, "Stop facts"). It polls its inputs every second, recomputes
only what moved, refreshes everything every minute, and runs the memory-index
cap and scratch reaper as a minute job. The composition-seam facts (the room
census, green receipts and per-room seam rows of every repository a claim or a
rostered seat names) refresh on their own key, per repository, so a slow one
never delays the lease facts. With no `helm web` running, every
claims exemption (a lane in gate, a lane approved) is refused at every stop
and `helm doctor` says so. `HELM_STOP_FACTS_LEG=1|0` decides for a server on
any other port.

A server running the leg **re-execs itself when its code changes on disk**:
once the tree's code digest has read the same for a second and the new tree
imports in a child interpreter, it waits out any snapshot write in flight,
releases the writer lock and runs its own command line again with `os.execv`
(same interpreter, port and environment). A tree that does not import is not
exec'd onto; the server keeps serving and logs why. No path unit or restart
step is needed for the stop facts to follow a land.
