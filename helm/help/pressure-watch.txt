pressure-watch [--post] [--json] | --install-timer — the fleet's own stall, read from OUTSIDE agents.slice by a one-minute app.slice user timer, so a stall of every seat at once is not starved out of its own detector. It keys on SUSTAINED PSI stall time of agents.slice cpu.pressure and memory.pressure (never on how full the slice is): a pass is hot when a kind's stall share since the last pass reaches HELM_PRESSURE_WATCH_PCT (20), and a hot run that lasts HELM_PRESSURE_WATCH_SUSTAIN_S (180) posts ONE row per episode to #main for @all and the owner, naming the top slices and processes by memory and by cpu and the seat that launched each, plus one push to the owner's phone; nothing more posts until the fleet reads clear for 120s. The episode is latched, logged and pushed from cgroup files before any process is read, and the process detail follows within 10s or the row says it is UNKNOWN. A process is named by its program only (the script, for an interpreter), never by any other argument. The same one-second window reads agents.slice's cpu.stat and the host's process count, so the cpu line also names SHORT-LIVED cpu (the slice's usage less every process sampled at both ends) and births/s; when helm's own processes (its bin/helm, bin/helm-hook, helm/*.py, python -m helm, the chat node, a fab client started from a helm checkout) are at least half the slice's cpu in a stall where cpu is a stalled kind, the row gains ONE line, HELM IS THE LOAD (P-1: fixed ahead of everything), and the pass files one open P0 task row titled 'P-1: helm is dragging the fleet (pressure-watch)' to the integrator, or comments on the open one, at most once per 30 min; a failure to read or file is said in the row. An UNKNOWN reading is said once, never read as calm. Bare reads and prints what a pass would do and whether the timer is installed, writing nothing; --post is the pass the timer runs (exit 1 = a stall is open or the reading is UNKNOWN); --json prints the reading; --install-timer writes and enables helm-pressure-watch.timer
