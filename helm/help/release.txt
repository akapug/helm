release nightly [status] | run [--repo P] [--timer] | --install-timer [--host HOST] — the nightly release dry run: can a release still be cut from trunk? `run` fetches trunk fresh, opens a read-only peek room at its tip and runs `scripts/release/release.py --nightly` there on the build host HELM_RELEASE_NIGHTLY_HOST names (`fab <host>`, never the hub): the release tool's own dry run, no push, no tag on a remote, no GitHub release, gitleaks required; it records one row (GREEN, RED naming the first step that refused, or MISSING when the dry run did not run) in `_global/.state/release-nightly/verdicts.jsonl` with the trunk sha, host, wall time and log path. Bare or `status` prints the streak, `N of 7 consecutive green nightlies; last red: <night> <step>`, counted over the timer's nights: a red night or a night with no green run ends it, a manual run neither counts nor breaks it, and a record that cannot be read whole reads UNKNOWN (exit 3); exit 0 at 7, 1 below. `--install-timer --host HOST` writes the host to $XDG_CONFIG_HOME/helm/release-nightly.env and enables helm-release-nightly.timer (02:30 nightly, persistent; HELM_RELEASE_NIGHTLY_TIMER=0 turns the install off)
